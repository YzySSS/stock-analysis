# Stock Analysis 前端设计文档 V1

更新时间：2026-04-27

## 目标

将当前 `stock-analysis` Web 控制台从“接口调试台”推进到“可实际使用的研究型选股前端”。

V1 目标不是做成券商 App，而是做成一套清晰、可信、便于研究与复盘的数据工作台。

---

## 一、站点结构（最终收敛版）

```text
首页 / Dashboard
├── 数据概览
├── 最近一次选股摘要
├── 历史补数 / 基本面同步状态
└── 快捷入口

选股中心
└── 选股结果

策略管理
├── 策略列表
└── 因子分析

股票详情页
└── 单票完整信息

跟踪复盘页
└── 选股后表现验证

数据状态页
└── 数据覆盖 / 同步状态 / 异常信息
```

说明：
- `策略说明`、`CI说明`、`因子说明` 不单独开页面。
- 统一采用页面内小问号（tooltip / popover）形式就地解释。
- `最新选股跟踪` 不再作为选股中心主模块长期保留，跟踪复盘保持独立页面。
- **因子分析主展示统一收口到“策略管理页”**，不再作为选股中心主区的一部分。

## 二、页面职责划分

## 2.1 首页 / Dashboard

作用：快速确认系统是否健康、数据是否够用、最近一次结果是否可信。

### 模块
- 数据状态卡片
  - 股票总数
  - 已补历史股票数
  - 基本面覆盖率
  - 最近交易日
- 最近一次选股摘要
  - 策略名称
  - 选股时间
  - 入选数量
  - Top 3 股票
- 任务运行状态
  - 历史补数
  - 基本面同步
  - 策略计算
- 快捷入口
  - 去选股中心
  - 去策略分析
  - 去跟踪复盘

---

## 2.2 选股中心

作用：展示“这次选了谁，用的是哪套策略，为什么选”。

### 2.2.1 选股结果

核心原则：
- 不直接展示 JSON
- 改为表格/条目 + 展开详情
- 结果页中保留轻量跟踪字段，但不替代独立复盘页
- **明确展示每条结果所属策略**，避免把选股结果与策略体系割裂

### 顶部信息区
- 当前策略名称 `?`
- 当前策略版本
- 选股时间
- 样本池数量
- 入选数量
- 数据更新时间

### 筛选栏
- 策略选择
- 选股日期 / run_id
- 行业筛选
- 最低分筛选
- 搜索股票
- 排序方式

### 列表展示字段（主表格）
- 股票名称
- 股票代码
- **选股策略**
- 行业
- 选股时间
- 入选价格
- 最新价格
- 区间涨跌幅
- 总分（主值）
- 总分下三因子摘要（换手 / 低波 / 反转）
- 排名
- 选股原因摘要（前 2 条 + 总条数）
- 风险提示摘要（前 2 条 + 总条数）
- 跟踪状态 / preview 状态
- 操作（保存 / 查看详情）

### 展开详情字段
- 分项得分（value / quality / stability / data / completeness）
- 三因子得分（turnover / lowvol / reversal）
- 原始指标摘要
- 详细选股原因
- 风险提示
- 最大浮盈
- 最大回撤
- 超额收益
- 最近更新时间
- 所属策略 / 版本
- 排名
- 行业兜底文案（若源数据为空则显示“暂无行业”）

### 选股页中的轻量跟踪字段
选股页允许直接展示以下复盘感知字段：
- 选股时间
- 入选价格
- 最新价格
- 区间涨跌幅
- 跟踪状态

但以下内容仍归独立“跟踪复盘页”负责：
- 完整收益轨迹
- 分策略复盘总结
- 胜率 / 超额收益统计
- 失败归因

## 2.3 策略管理页

作用：展示“系统里有哪些策略、每套策略由哪些因子构成、当前配置与数据质量如何”。

### 模块
- 默认策略卡片
- 策略数量
- 策略列表
- 策略详情区
- 因子分析区

### 策略列表字段
- 策略名称
- 策略 ID
- 版本
- 状态
- 标签
- 简介
- 是否默认
- 是否已迁移到当前执行链路

### 策略详情区
- 策略简介 `?`
- 当前版本
- 阈值 / 最大持仓数
- 核心因子摘要
- 适用说明（如研究中 / 旧版待迁移 / 当前默认）

### 因子分析区
作用：展示当前选中策略内部因子的有效性与解释链路。

#### 顶部信息
- 当前策略名 `?`
- 策略版本
- 样本池数量
- 最近交易日
- 计算时间

#### 因子表字段
- 因子名 `?`
- 中文名
- 类别
- CI 值 `?`
- 方向（正向 / 负向）
- 权重
- 覆盖率
- 缺失率
- 是否启用

#### 图表建议（V1 可先留接口）
- CI 横向对比条形图
- 因子覆盖率图
- 单因子分布图（可后补）

#### 就地说明设计
- **策略名旁 `?`**：策略简介、核心逻辑、主要因子、适用风格、当前版本
- **CI 值旁 `?`**：CI 是什么、当前值如何解释、样本区间、正负方向、标准化/缺失处理说明
- **因子名旁 `?`**：因子定义、数据来源、值越大/越小的含义、为何纳入当前策略

说明：
- 不再保留独立“计算说明页”
- 所有说明改为市面常见数据产品风格的就地提示
- **策略页承接因子分析主展示，选股中心不再重复放完整因子分析大表**

## 2.4 股票详情页

作用：展示单只股票的完整信息。

### 模块
- 基础信息
- 最新行情
- 基本面摘要
- 策略分项得分
- 因子暴露
- 入选原因
- 风险提示
- 跟踪复盘入口

---

## 2.5 跟踪复盘页

作用：展示“选完以后到底表现如何”。

### 模块
- 某次选股整体表现
- 各股票后续收益
- 最大回撤
- 超额收益
- 命中率 / 胜率
- 表现最好 / 最差股票
- 多次策略结果对比

### 与选股中心的边界
- **选股中心**：解释“这次谁入选、属于哪套策略”
- **跟踪复盘页**：验证“选得对不对”

### 当前交互约束（2026-04-28 晚间新增）
- 页面初始加载时，**不自动展示旧 run 结果**
- 用户修改阈值、数量、策略后，必须点击“运行”才展示本次 preview 结果
- `运行` 与 `保存` 解耦：
  - 运行只生成 preview 结果
  - 单条点击“保存”后，才进入 `selection_result` 并可在“跟踪复盘”中看到
- 任何涉及选股结果展示改动时，不得回退以下既有要求：
  - 排名显性展示
  - 原因 / 风险摘要显性展示
  - 行业为空时显示 `暂无行业`
  - 总分下方展示三因子摘要

一句话：
- 选股页 = 决策结果页
- 复盘页 = 结果验证页

## 2.6 数据状态页

作用：展示数据链路完整性，避免误把缺数据当策略问题。

## 四、API 改造建议

## 4.1 当前已有接口
- `POST /api/selection/run`
- `GET /api/selection/results`
- `GET /api/strategies`
- `GET /api/strategies/detail`
- `GET /api/tracking/latest`
- `GET /api/tracking`

## 4.2 当前主要问题
- `selection_result` 的重要信息主要塞在 `metadata_json` 中
- 现有 `selection.html` 页面仍偏“调试台”
- `策略管理页` 目前只展示列表，没有承接因子分析主展示
- 策略注册表目前只有一个正式策略，历史策略没有纳入页面体系
- 部分接口虽然能返回数据，但页面字段与策略设计目标还没完全对齐

## 4.3 V1 接口方向

### A. 升级 `GET /api/selection/results`
目标：返回真正面向前端页面的数据结构，并显式带出策略字段。

建议结构：

```json
{
  "run_id": "selection_20260427_120000",
  "strategy": {
    "id": "lowvol_reversal",
    "display_name": "低波动反转策略",
    "version": "v1"
  },
  "summary": {
    "selected_trade_date": "2026-04-23",
    "selected_at": "2026-04-27T12:00:00+08:00",
    "total_count": 20,
    "sample_size": 5200
  },
  "items": []
}
```

### B. `GET /api/strategies`
目标：返回多策略列表，并显式标明默认策略、当前策略、legacy 状态。

### C. `GET /api/strategies/detail`
目标：返回单策略详情 + 因子分析主数据。

### D. 跟踪复盘页继续使用独立接口
保留 `tracking` 路由作为复盘主入口，不再让选股中心承担完整复盘职责。

## 六、当前项目阶段下的设计原则

- 当前项目仍是研究型仓库，不必伪装成成熟券商终端
- 前端优先目标是：可信、清晰、便于验证策略输出
- 信息呈现应偏 dashboard / 数据工作台风格
- 避免过早演化为“因子研究平台”或“大而全证券 App”
- 优先把“结果可读、链路可查、数据可解释”做好
- **策略解释统一收口到策略页，结果展示统一收口到选股中心**

## 七、当前已确认的关键结论（已更新）

1. `选股中心` 主视图不展示 JSON
2. `最新选股跟踪` 不放在选股中心主区域，保留独立“跟踪复盘”页
3. **因子分析主展示放在 `策略管理页`，不再放在选股中心主区**
4. `计算说明` 不单独开页，而改用小问号就地说明
5. 选股结果列表必须补足时间、价格、轻量复盘字段与**选股策略字段**
6. `策略管理页` 不能只剩单一策略，应逐步纳入当前策略、V13 和 V12（legacy）
7. 正式开发优先级：**先策略页重构，再选股结果页补策略字段，再纳入多策略**
