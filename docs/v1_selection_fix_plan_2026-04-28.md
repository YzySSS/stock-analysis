# V1 选股功能修复计划（2026-04-28）

## 背景

当前用户已明确要求：

1. 先确保现有功能正常
2. 新接口接入（`daily_basic` / `cyq_perf` / `adj_factor` / `moneyflow` 等）统一放到 V2
3. 当前 V1 要优先修复以下体验问题：
   - 默认选股数量应为 3 支
   - 总分应统一为 100 分制
   - 默认分数阈值应为 60
   - 切换策略后要真正生效
   - 选股结果要真正可保存、可回看
   - 策略列表不能加载失败
   - 策略体系要至少做到 V1 可执行/可展示状态清晰可控

---

## 一、当前查实问题

### 1. 默认数量不对
- 前端默认 `limit=20`
- 后端默认 `limit=20`
- 不符合产品预期的默认 3 支

### 2. 分数体系口径混乱
- 当前执行链路分数为 `0 ~ 1`
- 部分策略配置阈值写成 `60`
- 页面筛选当前也偏向 `0~1` 逻辑
- 导致“总分 / 阈值 / 页面展示”三者不统一

### 3. 策略切换不真正生效
- `lowvol_reversal` 可执行
- `v13_three_factor` 注册了，但不兼容当前 `StockSelector` 协议
- 实际切换到该策略时会报错

### 4. 选股结果保存体验不稳定
- `lowvol_reversal` 实际可保存到 `selection_result`
- 但 run 结果数量、页面读取逻辑、策略切换后的查看体验不稳定
- 用户感知上容易误判为“没保存”

### 5. 策略列表与可执行状态表达不清
- 当前页面同时展示：可执行、实验中、legacy
- 但“可展示”与“可执行”界限不清
- 容易让用户以为所有策略都能运行

### 6. 当前并非真正统一的可插拔模块化
- 注册表/配置/页面外壳已经有了
- 但执行协议没有统一
- 属于“半模块化”状态

---

## 二、V1 修复目标

V1 不追求策略体系完美抽象，先确保：

> **能选、能切、能存、能看、规则一致。**

---

## 三、V1 修复范围

## P0 - 统一产品规则（优先最高）

### 修复项 1：默认选股数量统一为 3
- 前端默认值改为 3
- 后端默认值改为 3
- 默认策略配置 `max_picks` 改为 3

### 修复项 2：统一总分为 100 分制
- 所有执行链路输出改为 `0 ~ 100`
- 页面、阈值、策略说明统一使用 100 分口径

### 修复项 3：统一默认阈值为 60
- 默认策略配置阈值设为 60
- 页面最低分筛选默认值设为 60
- 运行链路阈值按 60 生效
- 明确规则：`3` 是最大入选上限，不是固定产出数；若仅 1 只达标则只展示 1 只，若 0 只达标则前端明确显示“无达标股”

---

## P1 - 修选股运行主链路

### 修复项 4：选股运行入口只暴露“当前可执行策略”
- 运行选股下拉框仅显示 `executable=true` 且协议已接通的策略
- 先避免用户选到会报错的策略

### 修复项 5：确保运行后保存与展示一致
- 每次运行都返回明确 `run_id`
- 保存条数与页面展示条数一致
- 结果页默认优先显示本次 run

### 修复项 6：策略切换后结果读取逻辑一致
- 切换策略后重新运行，应看到该策略对应结果
- 不能再出现“切了策略但结果还是上一套”的体验

---

## P2 - 修策略页状态表达

### 修复项 7：明确区分三种策略状态
- 可执行
- 仅展示
- 实验中 / 尚未接线

### 修复项 8：策略管理页与选股页状态一致
- 策略页展示的状态标签要和选股页下拉可选状态一致
- 避免页面互相打架

---

## P3 - V1 对“模块化”的最低修复

### 修复项 9：先不强行让所有策略都接入执行链路
V1 采取保守策略：
- 先确保 `lowvol_reversal` 稳定可用
- `v13_three_factor` 若未适配完成，则标记为实验中/暂不可执行
- `v12_legacy` 明确保留为仅展示

### 修复项 10：后续再统一执行协议
- 真正完整的可插拔协议统一，放到 V1.1 / V2 再处理
- 当前先以“用户可稳定使用”为第一目标

---

## 四、建议修复顺序

### 第二批
5. 修 run/save/result 展示一致性 ✅
6. 修策略切换后的结果读取逻辑 ✅

### 第三批
7. 修策略页状态表达 ✅
8. 明确 experimental / legacy / executable 口径 ✅

## 六、2026-04-28 当前已完成修复补充

本轮已继续完成以下 V1 修复：

1. **结果读取支持按 strategy_id 定位最新 run**
   - `/api/selection/results` 新增 `strategy_id` 查询参数
   - 当未指定 `run_id` 时，可按当前策略读取该策略最近一次运行结果
   - 避免“切了策略但看到的还是别的策略最近结果”

2. **run/save/result 主链路口径进一步对齐**
   - 结果接口返回 `requested_strategy_id`
   - summary 返回 `result_strategy_id`
   - 前端切换策略时会主动清空旧 `run_id`，重新按当前策略刷新结果
   - 运行后仍优先回显本次 `run_id`

3. **策略运行权限显式收口**
   - `StrategyService` 新增 `runtime_ready / experimental / display_only` 三类状态
   - 当前仅 `lowvol_reversal` 允许进入 V1 执行链路
   - `v13_three_factor` 明确标记为“实验中”，禁止误运行
   - `v12_legacy` 明确标记为“仅展示”

4. **策略页与选股页状态表达对齐**
   - 选股页策略摘要展示“可执行 / 实验中 / 仅展示”状态标签
   - 策略管理页统计口径改为：可执行策略、实验中/仅展示
   - 策略卡片与策略详情统一展示 availability 状态与说明

## 八、2026-04-28 晚间补充修复

本轮继续修了选股结果可读性问题：

1. **排名显性展示**
   - 主表“排名”列增加 `第 N 名` 提示
   - 详情区同步显示排名

2. **原因/风险显性展示**
   - 主表不再只留空白印象，直接显示前 2 条原因/风险摘要
   - 同时显示“共 N 条”，让用户知道不是没数据，而是摘要展示

3. **行业缺失时给出兜底文案**
   - 新增 `industry_display`
   - 当数据库行业为空时，前端统一显示 `暂无行业`
   - 这次确认 `sh.600000` 等记录在库里本身就是 `industry = NULL`，不是前端丢字段

4. **总分补充三因子明细**
   - 主表总分下方直接显示：`换手 / 低波 / 反转`
   - 详情区继续展开展示三因子得分 + 基础打分（value/quality/stability/data/completeness）

一句话：

> 现在选股结果页不该再给人“排名、原因、行业、因子得分像没出来”的感觉了；行业为空若仍存在，那是真数据源问题，不是页面漏渲染。
