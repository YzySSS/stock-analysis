# V1 选股功能修复计划（2026-04-28）

## 背景

当前用户已明确要求：

1. 先确保现有功能正常
2. 新接口接入（`daily_basic` / `cyq_perf` / `adj_factor` / `moneyflow` 等）统一放到 V2
3. 当前 V1 要优先修复以下体验问题：
   - 默认选股数量应为 3 支
   - 总分应统一为 100 分制
   - 默认分数阈值应为 60
   - 切换策略后要真正生效
   - 选股结果要真正可保存、可回看
   - 策略列表不能加载失败
   - 策略体系要至少做到 V1 可执行/可展示状态清晰可控

---

## 一、当前查实问题

### 1. 默认数量不对
- 前端默认 `limit=20`
- 后端默认 `limit=20`
- 不符合产品预期的默认 3 支

### 2. 分数体系口径混乱
- 当前执行链路分数为 `0 ~ 1`
- 部分策略配置阈值写成 `60`
- 页面筛选当前也偏向 `0~1` 逻辑
- 导致“总分 / 阈值 / 页面展示”三者不统一

### 3. 策略切换不真正生效
- `lowvol_reversal` 可执行
- `v13_three_factor` 注册了，但不兼容当前 `StockSelector` 协议
- 实际切换到该策略时会报错

### 4. 选股结果保存体验不稳定
- `lowvol_reversal` 实际可保存到 `selection_result`
- 但 run 结果数量、页面读取逻辑、策略切换后的查看体验不稳定
- 用户感知上容易误判为“没保存”

### 5. 策略列表与可执行状态表达不清
- 当前页面同时展示：可执行、实验中、legacy
- 但“可展示”与“可执行”界限不清
- 容易让用户以为所有策略都能运行

### 6. 当前并非真正统一的可插拔模块化
- 注册表/配置/页面外壳已经有了
- 但执行协议没有统一
- 属于“半模块化”状态

---

## 二、V1 修复目标

V1 不追求策略体系完美抽象，先确保：

> **能选、能切、能存、能看、规则一致。**

---

## 三、V1 修复范围

## P0 - 统一产品规则（优先最高）

### 修复项 1：默认选股数量统一为 3
- 前端默认值改为 3
- 后端默认值改为 3
- 默认策略配置 `max_picks` 改为 3

### 修复项 2：统一总分为 100 分制
- 所有执行链路输出改为 `0 ~ 100`
- 页面、阈值、策略说明统一使用 100 分口径

### 修复项 3：统一默认阈值为 60
- 默认策略配置阈值设为 60
- 页面最低分筛选默认值设为 60
- 运行链路阈值按 60 生效

---

## P1 - 修选股运行主链路

### 修复项 4：选股运行入口只暴露“当前可执行策略”
- 运行选股下拉框仅显示 `executable=true` 且协议已接通的策略
- 先避免用户选到会报错的策略

### 修复项 5：确保运行后保存与展示一致
- 每次运行都返回明确 `run_id`
- 保存条数与页面展示条数一致
- 结果页默认优先显示本次 run

### 修复项 6：策略切换后结果读取逻辑一致
- 切换策略后重新运行，应看到该策略对应结果
- 不能再出现“切了策略但结果还是上一套”的体验

---

## P2 - 修策略页状态表达

### 修复项 7：明确区分三种策略状态
- 可执行
- 仅展示
- 实验中 / 尚未接线

### 修复项 8：策略管理页与选股页状态一致
- 策略页展示的状态标签要和选股页下拉可选状态一致
- 避免页面互相打架

---

## P3 - V1 对“模块化”的最低修复

### 修复项 9：先不强行让所有策略都接入执行链路
V1 采取保守策略：
- 先确保 `lowvol_reversal` 稳定可用
- `v13_three_factor` 若未适配完成，则标记为实验中/暂不可执行
- `v12_legacy` 明确保留为仅展示

### 修复项 10：后续再统一执行协议
- 真正完整的可插拔协议统一，放到 V1.1 / V2 再处理
- 当前先以“用户可稳定使用”为第一目标

---

## 四、建议修复顺序

### 第一批（现在立即修）
1. 默认数量改 3
2. 统一 100 分制
3. 统一默认阈值 60
4. 运行入口只保留当前可执行策略

### 第二批
5. 修 run/save/result 展示一致性
6. 修策略切换后的结果读取逻辑

### 第三批
7. 修策略页状态表达
8. 明确 experimental / legacy / executable 口径

---

## 五、明确延期到 V2 的内容

以下内容不纳入本轮 V1 修复：
- `daily_basic` 新主线接入
- `cyq_perf`
- `adj_factor`
- `moneyflow`
- 更深层策略插件协议重构
- 新页面功能扩展

一句话：

> **V1 先救活当前产品体验，V2 再扩数据与架构。**
