# 冻结策略与受控样本外验证（2026-07-17）

## 1. 目标

在 DQ3～DQ5 已解决历史股票池、公告日基本面和指数成分主要前视偏差后，本切片开始回答另一个问题：现有策略在不改参数的条件下，是否具有稳定的净收益和超额收益证据。

本项目明确区分两类实验：

1. `historical_locked_holdout`：冻结当前配置后重跑历史区间，只用于排雷。由于策略研发过程可能已经看过这段历史，它永远不能升级 `validation_status`。
2. `prospective_oos`：验证窗口必须晚于冻结时的数据截止日。只有这一类协议具备真正未见样本资格；即使通过，也只生成 `oos_pass_candidate`，不会自动把策略改成已验证或可实盘。

## 2. 冻结内容

每条协议持久化到 `strategy_validation_protocol`，锁定：

- 策略 ID、版本、配置快照与 SHA-256；
- 策略实现、Selector、回测 Service/Repository 和股票池政策相关源码文件的逐文件及组合 SHA-256；
- 回测方法论版本 `close_signal_next_open_pit_index_universe_v5`；
- 股票池、日期、每日最大入选数、分数阈值；
- T 日收盘信号、T+1 开盘买入、下一交易日开盘卖出；
- 手续费 3 bps/边、印花税 5 bps/卖出、滑点 5 bps/边；
- 涨跌停、停牌和无开盘价成交约束；
- 沪深 300 下一开盘至再下一开盘的同周期基准；
- 预声明样本量与通过门槛。

执行前会重新计算当前配置和实现源码 hash。配置、实现代码或方法论只要有一项漂移，协议就 fail-closed，不允许用新版本污染旧冻结实验。V1 首轮协议因缺少代码指纹已中止并留痕，后续有效协议统一使用 `frozen_oos_protocol_v2`。

## 3. 预声明门槛

结构门槛：

- 至少 120 个交易日；
- 至少 120 笔有效交易；
- 基准覆盖不低于 98%；
- 有入选交易的日期必须形成完整收益，不允许把缺失退出价静默当成 0；
- run 成功，配置 hash、方法论和请求参数全部命中冻结值。

表现门槛：

- 扣成本后累计收益大于 0；
- 相对沪深 300 同周期累计超额大于 0；
- 年化 Sharpe 不低于 0.5；
- 最大回撤不低于 -20%；
- 正超额季度比例不低于 50%；
- 日均超额的 1,000 次固定种子 bootstrap 95% CI 下界大于 0。

任一结构门槛不满足时结论为 `inconclusive`；结构完整但表现未全部通过时按实验类型记录 `*_fail`。不根据结果回头修改门槛。

## 6. 使用入口

- 默认 dry-run：`scripts/run_backtest_oos_validation.py`。
- `--freeze` 才会持久化协议。
- `--execute-protocol <id>` 只执行已冻结且窗口闭合的协议。
- `--reconcile-protocol <id>` 在协调脚本中断后读取关联 run 并补齐终态，不重复跑回测。
- `--report-only <id>` 重读持久化报告。
- `--rebuild-report <id>` 用当前同版本报告引擎从不可变 run 明细确定性重建报告，不重跑策略。
- `--supersede-protocol <id> --replacement-protocol <id>` 保留旧协议审计记录并显式指向更严格替代协议。
- 页面和 API：`GET /api/backtest/validations`、`GET /api/backtest/validations/{protocol_id}`。

所有验证 run 使用 `is_system_test=1 + validation_baseline_id` 隔离，不进入默认正式回测列表，并受现有 retention 保护。

## 7. 已知限制

- 历史诊断不是未经观察的样本外，只能发现明显失效。
- 当前完整区间复权因子不足，V2 使用未复权一日收益；短持有能降低但不能消除除权噪声。
- bootstrap 为日收益独立重采样提示，不完整建模序列相关性。
- 指数历史成分仍是月度权重快照精度，不是精确调仓事件流。
- 通过前瞻协议也不等于可实盘；仍需人工复核、模拟盘和交易容量评估。
