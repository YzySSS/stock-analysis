# 舆情选股 v0.6.0：实施说明与启用清单

> 对应计划：`docs/sentiment_v06_modification_plan_2026-09-11.md`。本次实现基于
> `e512fd0`，策略 ID 为 `a_share_sentiment_v06`。截至 2026-09-15 仅完成本地
> 代码和离线验证；没有推送、部署、执行生产 migration，也没有启动固定时点采样。

## 1. 产品边界

- `0.6.0` 是独立、可显式选择的 `shadow_only` 研究策略，不覆盖冻结的
  `0.4.4` 或 `0.5.1`。
- 即使所有门槛通过，也只显示“研究候选”；结果不生成买卖计划，不自动下单，
  不自动晋级。
- 正式选股仍由用户手动触发。11:00、13:30、14:30 前瞻采样协议保持
  `preregistered_not_started / schedule_enabled=false`，启用需要单独审批。
- 全市场普跌提醒继续保持 `blocking=false / selection_allowed=true`。v0.6 只在
  自己的版本化入场条件中消费同类市场证据，不改变全局提醒合同。

## 2. 已实现链路

```text
NewsNow 原始记录与旧聚合（保留）
  -> 规范化事件/修订/证据/股票关系（migration 0037）
  -> 决策时点双时钟过滤（source_time + received_at）
  -> 直接催化轨 + 主题龙头轨召回
  -> 每轨六因子机会分 + 每轨不可补偿门槛
  -> 合并同股、主题/行业限额、研究候选或仅观察
  -> 不可变候选快照 -> Selection / Stock Detail / Tracking
```

### 2.1 事件证据合同

Migration `0037` 新增四张无外键表，适配生产迁移账号权限：

- `market_opinion_event`：当前事件索引与驱动力摘要；
- `market_opinion_event_revision`：事实版本；
- `market_opinion_event_evidence`：原文证据，重复写幂等且不覆盖；
- `market_opinion_stock_relation`：公司与事件的直接、主题、提及或负面关系。

事件角色固定为原始催化、催化进展、行情描述、观点/转载和风险事件。行情描述、
观点与转载可以作为市场反应证据，但不能升级业务事实的确认状态。决策后才收到的
旧时间戳新闻只保留数量诊断，不向历史事件文本或关系解析泄漏未来事实。

所有带时区时间先转换为 `Asia/Shanghai`，再与项目 MySQL `DATETIME` 使用的无时区
上海墙钟比较。来源时间、接收时间任一晚于决策截止，均不得参与当次决策。

### 2.2 双轨召回与六因子

两条候选轨分别计算、分别过门，再合并同一股票：

1. **直接催化轨**：需要可确认的增量事件及公司业务关系；
2. **主题龙头轨**：用主题映射扩召回，再检查当前同批次排名、广度、资金与分时承接。

六因子共用 0～100 尺度，固定权重为：催化质量 25%、后续驱动力 15%、业务关系
15%、同时点资金 15%、盘中价量承接 20%、筹码与成交容量 10%。缺失值保持未知，
不以 50 分回填；资金 `None`、真实 0 和负值分别处理。

每条轨道独立保存机会分、字段质量、缺失项和门控结果。合并时先比较
`conditions_met / observe / invalid`，同状态再比较机会分，避免高分泛主题遮住已满足
条件的直接催化，也避免总分补偿掉必要条件。

### 2.3 不可补偿门槛

`conditions_met` 必须同时满足：

- 分数、核心快照覆盖率与实时全市场覆盖率；
- 事件确认、业务关系和追加事件账本可追溯；
- 非防守市场状态；
- 个股资金分子/分母同交易日、同单位、来源与接收时钟均有效；
- 行情与资金均在截止前且不超过 TTL/时钟偏差；
- 分时路径完整并为持续承接或修复；
- 追涨、回撤、短窗收益、VWAP、事件后反应与主题广度符合规则；
- 非停牌、非退市、非不可成交涨停，且无已确认重大负面事件。

任一项缺失或失败只可为 `observe`；明确负面、失效或不可交易状态为 `invalid`。
输出同时保存 `decision_as_of`、`valid_until`、证据 ID、六因子版本、门控版本、
执行规则版本和评价协议哈希。

## 3. 页面和历史兼容

- Selection 增量展示候选轨、六因子、门槛、证据时点及“研究候选/仅观察”；
- Stock Detail 展示事件、主题、业务关系、有效期和接收时间；
- Tracking 保留精简研究上下文，但不为 v0.6 合成旧版买卖计划；
- Backtest 只保留历史路由和版本名称兼容，v0.6 能力状态仍为 `disabled`；
- 旧 API 字段不删除，新字段封装进现有不可变快照合同。

## 4. 前瞻评价协议

冻结文件为 `app/stock_selection/specs/sentiment_v06_forward_evaluation_v1.json`，
SHA-256 为 `037f57554eaa79dbf849d6f78e84714ec0235ec1e67b9c1bd1af816864582eb5`。

- 上海时区固定组：11:00、13:30、14:30；手动运行单独成池；
- 主指标：3 个交易日净超额收益；1/5 日为辅助；
- 决策后至少延迟 60 秒取首个可执行报价；往返成本 0.25%，包含双边各 5bp
  滑点及 0.15% 费用税费假设；
- 处理 T+1、停牌、涨跌停阻塞、跳空、未成交、延迟退出及日内价格范围校验；
- 首次终态不可被后续行情改写；空结果、数据失败、未触发和未成交全部进入分母；
- 时间顺序开发/校准/锁定测试、5 个交易日隔离、日期/事件分组、区块重采样及
  FDR 要求已经写入协议。

当前只提供冻结协议、纯执行模拟器、终态保护和分母统计。采集任务、持久化适配、
基准配对及报告任务尚未启用，这是防止在最小样本和晋级判据未完成预登记前产生
“边看边改”样本；不能把现有 Tracking 全观察期高低点当作正式绩效。

## 5. 已知能力边界

1. 没有显式 `event_identity_hint` 时，保守身份规则可能无法跨日期合并同一长期事件；
   不确定归并宁可拆开，不由 AI 猜测合并。
2. 当前主题扩召回只生产 `background_only` 关系；没有公司级可引用业务证据时，
   主题轨只能观察。公司公告等直接关系可由直接催化轨进入条件检查。
3. 盘中资金和分钟路径来自可变实时表，历史时点不能事后重建；正式评价只能使用
   当时已物化的输入快照和事件账本，不能拿后来补齐的数据冒充历史已知。
4. 事件账本从 migration 启用后前向积累，不回填伪造历史接收时间。
5. 策略、阈值和协议仅是待验证研究假设；工程通过不表示策略有效或可实盘。

## 7. 云端启用顺序（需另行批准）

1. 备份数据库、代码、Cron 与 systemd 配置并记录校验和；临时暂停
   `market_opinion_update` 写入，避免代码已切换但 `0037` 尚未应用。
2. 从待发布提交执行只读计划：
   `PYTHONPATH=. .venv/bin/python -m app.orchestration.migrate --pretty`。
3. 审核只新增 `0037` 后执行：
   `PYTHONPATH=. .venv/bin/python -m app.orchestration.migrate --apply --target 0037 --pretty`，
   再以 `--check --target 0037` 确认 37/37。
4. 恢复并手动运行一轮舆情采集，确认事件证据与同版本关系不会被覆盖、当前事件索引仅按合同更新、重复运行幂等，且旧聚合输出正常。
5. 显式执行一次研究快照：
   `.venv/bin/python scripts/materialize_sentiment_candidate_snapshot.py --strategy-id a_share_sentiment_v06 --allow-shadow`。
6. 验证 Selection、Stock Detail、Tracking、旧策略快照、API/Worker、队列和本地/公网
   健康；确认 v0.6 不产生 `trade_plan`，全市场提醒仍不阻断手动选股。
7. 每个交易日可安装 `09:32 / 11:02 / 13:32 / 14:32 / 18:57` 的研究快照
   物化，保证人工选择与晚间复盘有当日 `ready/passed` 快照。该任务不写
   `selection_result`，也不等价于启动预登记的固定时点前瞻观察。
8. `11:00 / 13:30 / 14:30` 前瞻协议仍保持未启动；待最小样本、主要判据、
   尾部限制和报告适配另行冻结并审批后，再单独启用 observation/outcome 链路。
